# Using telephony_kit in a Flutter app

telephony_kit gives Flutter apps Android's telephony APIs through JNI bindings
generated by jnigen. **Never** add a method channel or a Kotlin/Java plugin
class to reach these features; call the Dart API.

Android only. On iOS and other platforms every call throws, so guard with
`Platform.isAndroid` in shared code.

## Setup checklist

1. Add the dependency: `flutter pub add telephony_kit`. Minimum Android API 24.
2. Add the `<uses-permission>` lines for the features you use, and request
   them at runtime (for example with `permission_handler`). See
   [references/manifest.md](references/manifest.md) for every line.
3. For a **dialer** (own in-call screen, answering calls, notifications,
   conference, audio routes): add the DIAL intent filters, the
   `TelephonyKitInCallService` and deep-link opt out from
   [references/manifest.md](references/manifest.md), then call
   `requestDefaultDialer()`.
4. For a **call blocker** that is not a dialer: add
   `TelephonyKitCallScreeningService` and call `requestCallScreeningRole()`.
5. Declare only what you use: Google Play restricts call log, SMS and phone
   permissions to apps whose core purpose needs them.

## Core API

```dart
import 'package:telephony_kit/telephony_kit.dart';

final telephony = TelephonyKit.instance; // singleton, all calls synchronous
```

| Goal | Call |
| --- | --- |
| Open the system dialer | `openDialer(number)` (no permission) |
| Place a call (pick SIM) | `placeCall(number, phoneAccountId: id)` + `getPhoneAccounts()` |
| Become the dialer | `isDefaultDialer`, `requestDefaultDialer()` |
| React to calls | `callEvents` stream, `calls`, `call(id)` |
| Control a call | `PhoneCall.answer/reject(message:)/hangUp/hold/unhold/playDtmf/stopDtmf` |
| Dual SIM | `PhoneCall.selectablePhoneAccounts` + `selectPhoneAccount(id)` in `CallState.selectPhoneAccount`; `PhoneCall.phoneAccount`; `getPhoneAccountDetails()` |
| Why a call ended | `CallDisconnected` event, `PhoneCall.disconnectCause.displayText` |
| Extensions (`;`) | `PostDialWait` event, `PhoneCall.continuePostDial(true)` |
| Emergency | `isEmergencyNumber(number)` |
| Notifications | `showCallNotifications`, `missedCallNotificationsEnabled`, `clearMissedCallNotification()`, `proximitySensorEnabled` |
| Mute / audio | `setMuted`, `setSpeakerOn`, `supportedAudioRoutes`, `setAudioRoute`, `bluetoothDevices`, `selectBluetoothDevice` |
| Several calls | `swapCalls()`, `PhoneCall.merge/conferenceWith/swap/splitFromConference/children/parent` |
| Search call log | `searchCallLog(query:, types:, from:, to:, limit:)` |
| Change call log | `deleteCallLogEntries(ids)`, `deleteCallLogForNumber`, `markMissedCallsRead()` |
| Contacts (pick / caller name) | `searchContacts(query)`, `lookupNumber(number)` |
| Contact details | `getContacts(query:, limit:)`, `getContact(id)` return every field (`ContactDetails`) |
| Add / edit / delete contacts | `addContact(details)`, `updateContact(details)` (read, `copyWith`, save), `deleteContact(id)`, `deleteContacts(ids)`, `setContactStarred(id, bool)` (WRITE_CONTACTS) |
| Block calls | `screening` rules, `screenedCalls`, system list: `canBlockNumbers`, `blockNumber`, `unblockNumber`, `getBlockedNumbers` |
| SIM / network | `getSimCards()`, `getNetworkInfo()`, `signalLevel`, `networkGeneration`, `networkEvents` |
| USSD / voicemail | `await sendUssd('*100#')`, `voicemailNumber`, `callVoicemail()` |
| SMS | `await sendSms(to, text)`, `searchSms(query:)` |
| Dial links | `takeDialNumber()` on start and resume |

Full signatures and return types: [references/api.md](references/api.md).

## Patterns

**In-call screen.** Listen to `callEvents` once (for example in your root
widget), and on every event re-read `telephony.calls`, keeping calls whose
`state.isLive`. Show the in-call UI while that list is not empty; prefer the
`CallState.ringing` call, then `active`. Re-check `isDefaultDialer` in
`didChangeAppLifecycleState(resumed)`.

```dart
telephony.callEvents.listen((_) {
  final live = telephony.calls.where((c) => c.state.isLive).toList();
  setState(() => _calls = live);
});
```

**Handle every call state.** Besides ringing and active, show a SIM picker
for `CallState.selectPhoneAccount`, a "Send remaining digits?" prompt on
`PostDialWait`, and `disconnectCause.displayText` briefly when a call ends
with `isFailure`. An exhaustive `switch` over `CallEvent` must cover
`CallAdded`, `CallStateChanged`, `CallDisconnected`, `CallRemoved`,
`PostDialWait` and `AudioStateChanged`.

**Errors.** Android failures (missing permission, no role) throw
`TelephonyException`. Check `hasPermission(TelephonyPermission.x)` first and
catch around each call. Control methods on `PhoneCall` return `false` when the
call no longer exists instead of throwing.

**Searches** run synchronously on the UI isolate. Always pass a `limit`, and
debounce search-as-you-type.

**Caller name.** `PhoneCall.displayName` can be empty; fall back to
`lookupNumber(call.number)?.displayName`, then the number. Cache the result per
call; do not look it up on every frame.

**Editing contacts.** Read with `getContact(id)`, change with `copyWith`, then
`updateContact`. It *replaces* name, phones, emails, addresses, company,
nickname, websites, note and birthday, so always start from the full contact
or fields are lost. Photos and groups are untouched. Deleting cannot be
undone: confirm with the user first. Need `WRITE_CONTACTS` as well as
`READ_CONTACTS`; `Permission.contacts` requests both.

**Screening rules** persist on the device and apply when the app is closed.
Set them once from settings UI; do not rewrite them on every app start.

## Pitfalls

- Calls, notifications, conference and audio APIs only work while the app is
  the **default dialer** and declares `TelephonyKitInCallService`. Otherwise
  `calls` stays empty and `callEvents` never fires.
- Keep `android.telecom.IN_CALL_SERVICE_RINGING` set to `false` unless you
  play the ringtone yourself, or incoming calls ring silently.
- Without `flutter_deeplinking_enabled=false`, tapping a phone number in other
  apps opens your app with an unknown route and crashes navigation.
- Missed call notifications need `TelephonyKitMissedCallReceiver` in the
  manifest, protected by `MODIFY_PHONE_STATE`; without it the system shows
  its own.
- Never block emergency numbers in your own logic; check
  `isEmergencyNumber` first (the package's screening already does).
- `canBlockNumbers` and the system block list need the default dialer or SMS
  role; fall back to `screening.blockNumber`.
- Silencing calls needs Android 10+, USSD needs Android 8+, Bluetooth device
  lists need Android 9+ and `BLUETOOTH_CONNECT` for names on Android 12+.
- Emulators cannot test call waiting, Bluetooth, USSD replies, voicemail or
  dual SIM. Use `adb emu gsm call <number>` and `adb emu sms send <number> <text>`
  for the rest.

## Not possible on Android for any third-party app

Call recording, reading the IMEI, and replacing the phone app on iOS. Tell the
user instead of trying workarounds.
