# AGENTS.md

Instructions for AI coding agents (Claude Code, Codex, Cursor, Copilot and
others) working **on** this repository. If you are building an app that
**uses** telephony_kit, read [`skills/telephony-kit/SKILL.md`](skills/telephony-kit/SKILL.md)
instead.

## What this is

`telephony_kit` is a Flutter plugin for Android telephony and dialer apps:
placing and controlling calls, the default dialer role, in-call UI events,
call screening and blocking, contacts and call log search, SIM and network
info, USSD and SMS.

**The one rule:** Dart talks to Android only through JNI bindings generated by
[jnigen](https://pub.dev/packages/jnigen). Do not add method channels, event
channels, Pigeon or `pluginClass` registration. A pull request that adds them
will be rejected.

## Layout

```
lib/telephony_kit.dart            Public exports. Keep this list small.
lib/src/telephony_kit_impl.dart   TelephonyKit, PhoneCall, CallScreeningSettings.
lib/src/models.dart               Plain Dart data types and enums.
lib/src/permissions.dart          TelephonyPermission name constants.
lib/src/search.dart               Pure Dart search helpers (unit tested).
lib/src/contacts.dart             Pure Dart contact rows <-> ContactDetails.
lib/src/vcard.dart                Pure Dart vCard reader and writer.
lib/src/analysis.dart             Pure Dart call log stats, duplicates, SMS threads, parsers.
lib/src/formatting.dart           Pure Dart CallTimeFormatter (times, durations, time zones).
lib/src/phone_numbers.dart        Calling codes, country of a number, PhoneNumberInputFormatter.
lib/src/bindings.g.dart           GENERATED by tool/jnigen.dart. Never edit by hand.
tool/jnigen.dart                  Binding generator config + method allow list.
android/src/main/java/...         The only Java: services, receivers, helpers.
example/                          A full dialer app that exercises every API.
test/                             Unit tests for pure Dart code.
skills/telephony-kit/             Agent skill for apps that use the package.
```

## When Java is allowed

Write Java only for what jnigen cannot express:

- Android components the system instantiates: `InCallService`,
  `CallScreeningService`, `BroadcastReceiver`, and `CallActionActivity`
  (notification buttons that must open the app use an activity, because
  since Android 12 a receiver may not start one).
- Abstract callback classes Android requires you to subclass
  (`TelephonyCallback`, `UssdResponseCallback`, `Call.Callback`,
  `SubscriptionManager.OnSubscriptionsChangedListener`).
- Work that must run when Flutter is not running (screening rules, the
  `CallBubble` overlay window and its app visibility tracking).

Keep Java classes thin. Expose static methods with primitive or `String`
parameters, and deliver callbacks through small Java **interfaces**
(`CallEventListener`, `ScreeningListener`, `NetworkEventListener`,
`ResultListener`) that Dart implements with `X.implement($X(...))` and
`method$async: true`. Everything else (framework services, content providers,
roles, intents) is called from Dart through the generated bindings.

One more case is allowed: a bulk scan whose result Dart only needs in
summary (for example `ContactPager`, which collects thousands of contact ids
natively). Reading each cell through JNI is slow, so do the scan in Java and
return a small result such as an id slice.

Classes only Android talks to are excluded from bindings in the `_systemOnly`
set in `tool/jnigen.dart`.

## Adding or changing an Android API

1. Add the class to `classes` and its members to `_androidAllowList` in
   `tool/jnigen.dart`. Only list what you use; the allow list keeps the
   generated file small and free of hidden APIs.
2. Regenerate (needs a real Android SDK with `platforms/android-36` or `35`):

   ```sh
   export ANDROID_SDK_ROOT=~/Library/Android/sdk   # or ANDROID_HOME
   flutter pub get
   dart run tool/jnigen.dart
   ```

3. Overloaded Java methods get suffixes (`query$1`, `put$3`). Suffixes depend
   on the SDK jar, so after regenerating, run `flutter analyze` and fix any
   renamed call sites. Always regenerate from the real SDK, never from a
   framework jar such as Robolectric's (it contains hidden methods).
4. Wrap the call in `lib/src/telephony_kit_impl.dart` behind a Darty API:
   Dart types in and out, enums instead of int constants, `TelephonyException`
   instead of `JThrowable` (use the `_guard` helper), and dartdoc that names
   the permission and minimum Android version needed.
5. Check `Build.VERSION.SDK_INT` (`_sdkInt` in Dart) before calling APIs newer
   than minSdk 24.

## Conventions

- Public API is synchronous unless Android is asynchronous (USSD, SMS) or it
  is a stream of events. Streams are broadcast and register the Java listener
  in `onListen` and unregister in `onCancel`.
- Content provider queries go through `_queryRows`, filter in SQL with
  `?` arguments (never string concatenation of user input), and cap results
  with `limit`.
- Number matching ignores formatting and treats a leading `0` and a country
  code as the same number (`numberSearchPatterns`, `CallScreening.sameNumber`).
- New public types go in `models.dart`; export new public classes from
  `lib/telephony_kit.dart`.
- Every new feature needs: dartdoc, a CHANGELOG entry, a README section, the
  manifest snippet if one is needed, an example-app screen or control, and
  unit tests for any pure Dart logic.

## Checks before you commit

```sh
dart format lib test example/lib tool
flutter analyze                      # root
(cd example && flutter analyze)
flutter test
flutter pub publish --dry-run        # must report 0 warnings
```

All must pass. Commit generated `lib/src/bindings.g.dart` together with the
Java or config change that produced it.

## Testing on a device or emulator

Most of the package can only be verified on Android:

```sh
cd example && flutter run
adb shell cmd role add-role-holder android.app.role.DIALER dev.telephonykit.telephony_kit_example
adb emu gsm call 5551234        # incoming call
adb emu gsm accept 5551234      # remote side answers an outgoing call
adb emu gsm busy 5551234        # remote side is busy
adb emu gsm cancel 5551234      # remote side hangs up
adb emu sms send 5551234 hello  # incoming SMS
```

Grant runtime permissions with
`adb shell pm grant dev.telephonykit.telephony_kit_example android.permission.<NAME>`.
For the call bubble also grant the overlay permission with
`adb shell appops set dev.telephonykit.telephony_kit_example SYSTEM_ALERT_WINDOW allow`,
turn it on in the Device tab, start a call and press Home. For answering from
the notification, send the app to the background, `adb emu gsm call 5551234`,
and tap Answer on the heads-up notification; the call screen must open.

The emulator cannot test call waiting, Bluetooth or earpiece routes, real USSD
replies, voicemail or dual SIM; say so in your report instead of claiming
they work.

## Things that are not possible

Do not try to add: call recording (blocked for third-party apps since
Android 10), IMEI or serial access, replacing the iOS phone app, or reading
another app's calls without being the default dialer or holding the call
screening role.
